# 设备端隐藏语音指令检测/拦截原型 (Hidden Voice Command Guard)

纯 C++17、零外部依赖的实时音频前处理检测器，针对两类已公开的隐藏语音指令攻击：

- **通道 A — 超声波调制指令（DolphinAttack 类）**：把语音包络调制到 17–23.5 kHz
  载波上，人耳不可闻但 MEMS 麦克风可接收。
- **通道 B — 音乐掩蔽的带内指令（CommanderSong 类）**：指令以负 SNR 混在音乐里，
  经小型扬声器重放，人听着是音乐、设备却听成指令。

所有测试音频均由 `src/synth.cpp` 物理建模合成，无需外部数据集。

## 目录结构

```
include/dsp.hpp        FFT、汉宁窗、biquad 滤波、mel 滤波器组等 DSP 原语
include/synth.hpp      合成器接口
include/detector.hpp   流式检测器（校准 + 双通道判决 + 时间投票/迟滞）
src/synth.cpp          9 类音频 + 4 种麦克风频响曲线 + WAV 输出
src/eval.cpp           评估主程序（检出率/误拦率/Wilson 区间/耗时基准）
src/demo.cpp           每类导出一个 WAV 到 data/
src/integration_example.cpp  设备端环形缓冲集成与实时静音拦截示例
tools/                 纯标准库 Python 分析脚本（特征分布、ROC 扫描）
```

## 构建与运行

```bash
make            # 产出 build/eval、build/demo、build/integration_example
./build/eval                       # 完整评估，打印检出率/误拦率/耗时
./build/eval --csv build/scores.csv  # 额外导出逐帧特征
./build/demo data                  # 生成每类示例 WAV
./build/integration_example        # 流式拦截端到端示例
python3 -I tools/analyze_scores.py build/scores.csv
```

## 检测原理

### 麦克风自适应（应对不同麦克风频响）

开机时用一段已知干净的环境音做一次校准，逐 FFT bin 估计对数功率谱的中位数和
MAD（稳健的噪声底与离散度）。之后所有电平类判据都用**归一化 z 分数或能量比**，
不依赖绝对增益，因此不同麦克风的高频滚降、灵敏度差异不会移动判决边界。

### 通道 A：超声波调制（DolphinAttack 类）

四个同时成立的条件 + 5/8 帧投票 + 24 帧迟滞：

1. 17–23.5 kHz 能量占总能量比例 > 0.30（频段被超声主导，正常音频该值约 0.02）；
2. 该带能量相对校准噪声底显著抬升；
3. 带能量轨迹的 **3–12 Hz 音节速率调制功率占比** > 0.18（语音包络特征）；
4. 频谱不坍缩到 1–2 个纯音峰（峰度 < 0.88，至少 3 个活跃 bin）。

**为什么稳态超声啸叫不会被误拦**：电子镇流器/开关电源的超声啸叫没有音节速率
调制（条件 3 失败），且能量集中在 1–2 个纯音上（条件 4 失败）。注意调制窗口特意
取 3–12 Hz 而非 1–12 Hz，以排除啸叫的慢漂移/颤音经麦克风滚降曲线后形成的低频调幅。

### 通道 B：带内重放/活体门（CommanderSong 类）

带内隐藏指令与正常音乐在频谱统计上高度重叠（见下“能力边界”），因此通道 B 采用
**重放路径 vs 活体嗓音的物理差异**作为可辩护的判据。小型/电话级重放扬声器是带通
器件，同时缺两端：

- 低频端（~180–300 Hz 以下）重放不出胸腔/声门能量；真人嗓音在 40–150 Hz 带有随
  音节调制的声门能量；
- 高频端（~3.4–5.5 kHz 以上）重放不出清辅音擦音；真人嗓音在 5–7.5 kHz 带有随音节
  开关的擦音调制。

判决（在约 0.7 秒滑窗中位数上，含 64 帧硬预热和 12/16 帧持续投票）：

1. 存在调性音乐床（谱平坦度低）；
2. 存在音节速率调制和语音带能量；
3. 活体门：窗口内 40–150 Hz 声门调制中位数 **和** 5–7.5 kHz 擦音调制中位数都低于
   活体水平 → 判为重放指令。真人说话（无论是否盖着音乐）两者都会升高而放行；
   纯音乐的镲片持续抬高高频擦音调制中位数，也被放行。

## 评估结果

配置：48 kHz、1024 点 FFT、512 点跳帧（10.67 ms/帧）；每类 25 个片段 × 4 种麦克风
曲线 = 每类 100 个片段，共 900 个片段。

| 类别 | 类型 | 拦截数/总数 | 拦截率 |
|---|---|---|---|
| ultrasonic_attack（超声攻击）| 攻击 | 100/100 | **100%** |
| commander_song（音乐掩蔽指令）| 攻击 | 8/100 | 8% |
| ultrasonic_whine（稳态超声啸叫，对抗性良性）| 良性 | 0/100 | 0% |
| farfield_speech（远场说话）| 良性 | 0/100 | 0% |
| farfield_noisy（低信噪比远场）| 良性 | 0/100 | 0% |
| speech_over_music（盖着音乐说话）| 良性 | 0/100 | 0% |
| music_only（纯音乐）| 良性 | 0/100 | 0% |
| ambient_noise（环境噪声）| 良性 | 0/100 | 0% |
| near_silence（近静默）| 良性 | 0/100 | 0% |

- **总攻击检出率：108/200 = 54.0%**（95% Wilson CI 47.1%–60.8%）
- **良性误拦率：0/700 = 0.00%**（95% Wilson CI 0%–0.55%）
- 其中超声攻击检出率 **100%**、超声相关良性误拦 **0%**。
- 实时成本：约 **85 µs/帧**，占单核预算（10.67 ms）的 **0.8%**，约 120 倍实时余量。
- 端到端集成示例中，4 秒超声攻击 93% 的帧被实时静音，良性语音 0 帧被静音。

## 能力边界（重要，如实说明）

通道 B 对**深度掩蔽的带内指令检出率仅 8%，这是轻量前处理的物理边界，不是调参问题**。
开发中系统尝试了 8 类特征（谱平坦度、音节调制谱、跨带相干性、调制集中度、谱通量、
起振间隔不规则度、共振峰显著度、谐波梳状比、高频滚降等），片段级 ROC 扫描一致显示：

- 当指令以 −2～−7 dB 藏在全频带、含镲片/打击乐的真实音乐里时，指令波形在统计上被
  音乐床淹没，**纯音乐与“音乐+隐藏指令”在所有这些轻量特征上的分布大面积重叠**；
- 片段级 ROC 显示权衡是：约 1% 良性误拦只能换约 30% 检出，要高检出就得大量误拦
  正常音乐。本实现选择了**零误拦的保守工作点**，优先保证不误伤正常音乐和真人说话。

工程上正确的纵深防御是把这一层放在 ASR 之前做**第一道过滤**（对超声攻击近乎完美、
对可识别重放特征的带内指令有效），深度掩蔽的残余风险交给后端：ASR 侧的命令确认/
二次校验、声纹活体、关键命令的多模态确认等。若放宽误拦预算，可下调
`livenessMax`/`hfSyllMax` 用 `tools/roc_sweep.py` 重新选择工作点。

## 实时性与资源

- 每帧一次 1024 点 FFT + 16 个 mel 带 + 若干一阶/二阶统计，无堆分配热点（状态复用）；
- 全部浮点运算，无超越函数密集调用；在桌面 ARM64 上约 85 µs/帧，移植到典型
  设备端 DSP/NPU 前的 Cortex-A 级核仍有充足余量；
- 检测器状态约几 KB，无动态大缓冲，适合常驻音频前处理管线。

## 合成数据的物理建模

- 伪语音：抖动声门脉冲经 3 个时变共振峰 + 擦音噪声，带真实 4–10 Hz 音节调制和
  40–150 Hz 胸腔成分；
- 伪音乐：三和弦垫音（失谐振荡器+颤音）、五声音阶旋律、打击乐、高通镲片（6–12 kHz）；
- 超声攻击：伪语音包络（整流+低通）调制 5 个展宽子载波（17.5–22.5 kHz）；
- 重放指令：先经高通（~180/300 Hz）+ 低通（~3.4/5.5 kHz）带通，再软削波，模拟小型
  扬声器的带通特性与非线性；
- 4 种麦克风曲线：平直参考、廉价 MEMS 高频滚降、带 12 kHz 峰的驻极体、低抬升+纹波，
  并叠加自噪声，验证校准/归一化对麦克风差异的鲁棒性。
